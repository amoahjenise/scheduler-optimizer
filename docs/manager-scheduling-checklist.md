# Manager Scheduling Checklist

This checklist is intended for day-to-day scheduling review and manager oversight. It is intentionally simple and operationally focused.

> Safety note: Keep this document generic and do not include names, employee numbers, patient records, or sensitive operational details.

## 1. Before you build or review a schedule

### Confirm the setup

- [ ] Shift codes match the actual unit pattern
- [ ] Staffing roles are still correct for the current team structure
- [ ] Staffing teams are up to date and consistent
- [ ] Weekend rotation settings are aligned with the current operational policy
- [ ] Leave and off requests are reviewed before finalizing coverage

### Review the staffing minimums

- [ ] Daily coverage minimums are understood for the time period
- [ ] Coverage is checked by day, evening, and night blocks
- [ ] No obvious gap is left in the first pass of the schedule
- [ ] Any required special coverage needs are identified before optimization

### Check the data quality

- [ ] Existing assignments are valid and not obviously stale
- [ ] Accepted leave requests are respected
- [ ] No broken or mismatched shift codes are present
- [ ] Schedule range matches the intended planning window

---

## 2. During schedule review

### Coverage quality

- [ ] Minimum coverage is met across the schedule
- [ ] Daily and time-block coverage is balanced, not just total headcount
- [ ] No single team or small subset is carrying too much of the workload
- [ ] The schedule does not create avoidable overuse of a few staff members

### Rule and constraint checks

- [ ] Rest windows are respected
- [ ] Consecutive work patterns are within reasonable limits
- [ ] Shift-code logic matches the actual schedule model
- [ ] Off and leave periods are not overridden without a valid reason
- [ ] Assistant manager leadership coverage remains appropriate

### Team and operational checks

- [ ] Staffing teams are being used consistently
- [ ] Weekend rotation is fair and intentional
- [ ] Assigned roles still make sense for the current unit structure
- [ ] Schedule remains readable and operationally understandable

---

## 3. After the scheduler runs

### Quick quality pass

- [ ] The schedule still meets minimum staffing after optimization
- [ ] Day and night blocks look realistic and balanced
- [ ] There are no obvious unjustified gaps or heavy concentration of assignments
- [ ] Leave and off requests were not ignored without explanation
- [ ] No awkward or impossible shift sequences remain

### Final manager review

- [ ] Confirm the schedule is safe to publish
- [ ] Record any exceptions or manual adjustments made after generation
- [ ] Ensure the plan is consistent with the unit's working model
- [ ] Publish or share only approved final versions

---

## 4. Red flags to look for

Flag the schedule for manual review if you see any of these patterns:

- [ ] A day is only covered by one team or one small subset of staff
- [ ] Coverage is good in total but weak in one shift block
- [ ] A nurse is repeatedly assigned in a pattern that looks unsustainable
- [ ] Time-off requests are not respected
- [ ] Weekend rotation is heavily skewed without justification
- [ ] Shift codes are used inconsistently or incorrectly
- [ ] The schedule looks mathematically valid but operationally unrealistic

---

## 5. Weekly manager routine

### Weekly operating rhythm

- [ ] Review staffing setup at the start of the week
- [ ] Check leave and off-request updates before scheduling
- [ ] Review the generated coverage before approval
- [ ] Apply manual fixes only where the algorithm is clearly not aligned with unit policy
- [ ] Re-check the final schedule before publishing or sending it onward

### Good schedule definition

A good schedule is usually one that:

- meets minimum coverage
- respects leave and constraints
- keeps workload balanced
- remains understandable for the staff team
- is safe and stable enough to operate without emergency correction

---

## 6. Simple decision rule

If the schedule is safe, balanced, and matches the unit's rules, it is usually acceptable.

If it is only numerically valid but unrealistic, unclear, or unfair, it should be reviewed manually before approval.
